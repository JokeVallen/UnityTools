### 💡 设计理念

传统的战斗框架在解耦和易用性上往往会牺牲相当大的性能。例如，高频装箱拆箱、大量的虚函数调用、Tick 迭代中中途修改集合引发迭代器崩溃等。

底层技术审美在于**以极致的泛型特化、值类型包装、以及安全的双缓冲时序队列**建立契约：

1. **零 GC（Zero-GC）流转**：通过实现 `readonly struct` 的属性包装器 `Attribute<T>` 和可选值包装器 `Optional<T>`，所有核心计算路径均在线程栈上进行值传递，彻底消除了托管堆垃圾产生的可能性。
2. **消灭虚函数跳转**：通过将战斗公式抽象为特化结构体 `where TFormula : struct, IAttributeFormula<TResult>`，享受编译期的方法内联（Inlining），使公式计算效率直逼原生机器指令。
3. **时序防御性设计（防爆）**：通过双缓冲的 `PendingCommand` 延迟命令队列接收 Buff 的状态流转，彻底杜绝了因伤害触发状态变更、进而导致迭代中途修改集合引起的迭代器崩溃问题。

### 🔍 具体功能说明

#### 1. 轻量化组件组装与时序控制机制 (`Component System`)

* 框架建立了严谨的组件式开发骨架，核心接口包括 `IComponent`（通用组件标识）、`IAttachableComponent`（具备附着与解附回调的生命周期组件）以及 `ITickableComponent`（支持帧推进更新的组件）。
* 实体或容器通过实现 `IComponentAttachable` 接口，可动态、安全地对各种战斗组件（如 `BuffComponent` 等）进行生命周期的动态挂载、卸载及高频检索，构建出高内聚、低耦合的实体逻辑形态。

#### 2. 极致强类型属性管理 (`AttributeCollection`)

* 属性系统采用特化的双层字典结构承载，外层由 `Type` 标识存储容器，内层为强类型的字典。针对不同的属性类型（如 `(RoleAttribute, int)`、`(string, float)`）进行存储，绝不发生 `object` 的高频装箱拆箱开销。
* 属性的读取与修改均在 $O(1)$ 时间复杂度内完成，且支持动态注册属性变更的响应回调事件。

#### 3. 无损的公式计算引擎 (`AttributeEvaluator`)

* 计算器利用只读视图 `AttributeReader` 读取属性，配合显式声明为结构体的战斗公式进行计算。
* 彻底抹平了传统委托、策略模式带来的虚函数指针跳转成本，为高并发的战斗伤害数值结算提供核心算力引擎。

#### 4. 强安全性的双缓冲 Buff 系统 (`BuffComponent`)

* 实现了标准的 `ApplyTo`（应用）、`Tick`（帧推进）、`RemoveFrom`（卸载）三阶段 Buff 生命周期。
* 引入了 `PendingCommand` 延迟队列机制。在 Buff 的 Tick 期间，任何由业务层发起的 Buff 添加或删除指令均会暂存于安全队列中，在当前帧遍历安全结束后统一、顺序执行，保证高频混战时的绝对稳定。
* 提供契约标记，支持高度自定义：
* 可堆叠 Buff 的重载契约 (`IStackableBuff`)。
* 标记不触发全局事件、防消息风暴的优化契约 (`INoGlobalBroadcastBuff`)。
* 标记不需要额外上下文、省去高频分配的极速契约 (`INoExtraContextBuff`)。

#### 5. 高度解耦与数据驱动的技能执行管线 (`ISkillExecutor`)

* 拆分了“技能校验与管线总管” (`ISkillExecutor`)、“作用目标筛选” (`ISelector`)、“瞬时战斗效果触发” (`IEffect`) 和“持续性状态残留机” (`IBuff`)。
* 所有的上下文对象（`EffectContext`、`BuffContext`、`SkillExecutorContext`）均采用只读结构体（`readonly struct`），实现了运行期的高效流转。

#### 6. 跨端架构支持（Client / Server 同源）

* 核心逻辑纯粹基于标准 C#，没有任何一行代码依赖 Unity 表现层，天然具备在服务器端无感运行的能力。
* 在客户端中，可通过 `ITypedContext` 将 Unity 的 `GameObject` 或表现组件擦除塞入上下文；而在服务器中，上下文仅传递纯数据。双端可以直接复用完全一致的物理战斗计算源码。
