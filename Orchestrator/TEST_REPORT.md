## 一、单元测试

单元测试覆盖了三个版本的全部公开 API 和核心执行逻辑，确保功能正确性和接口契约符合预期。所有测试均通过，无失败用例。

### 1.1 Task 版本（xUnit）

共 **33** 个测试用例，分布在以下测试类中：

| 测试类 | 测试内容 | 用例数 |
|--------|----------|--------|
| `StepResultTests` | `Continue` / `Break` / `Fail` 工厂方法的正确性 | 4 |
| `ExecutionResultTests` | `ExecutionResult` 与 `StepExecutionResult` 的属性初始化及边界情况 | 5 |
| `InterfaceContractTests` | `IStep`, `IBehavior`, `IExecutionResult`, `IStepExecutionResult` 接口的契约行为（使用 Mock） | 5 |
| `InterruptionPolicyTests` | `Strict` / `DependencyBased` / `Ignore` 三种中断策略的正确性 | 3 |
| `OrchestratorBuilderTests` | Builder 的构建过程、参数校验、多步骤多行为组合构建 | 5 |
| `OrchestratorTests` | 编排器完整执行流程：单步、失败、中断、钻石依赖、行为链、取消令牌、复杂 DAG、总耗时等 | 11 |

**关键验证点**：
- 步骤结果封装正确，`Continue` 提供输出，`Break` 提供可选输出，`Fail` 携带异常。
- 执行结果包含完整的步骤审计列表、总耗时，且成功状态与终步流程一致。
- 行为管道按添加顺序形成洋葱模型，执行顺序符合“外层先进后出”的预期。
- 三种中断策略在“中间步骤中断”的场景下，阻断范围和后续步骤执行数量与预期完全一致。
- 取消令牌可以随时中断执行，并正确抛出 `OperationCanceledException`。
- 钻石依赖（A→B、A→C、B→D、C→D）的依赖顺序被严格遵循，无步骤重复执行。

### 1.2 ValueTask 版本（xUnit）

共 **33** 个测试用例，测试类结构和覆盖内容与 Task 版本完全对应，仅替换为 `ValueTask` 相关接口和 `ValueTaskOrchestrator`。

**关键差异**：
- 取消测试通过 `AsTask()` 转换后断言异常类型，确保 `ValueTask` 的异常传播语义正确。
- 同步完成路径的 `ValueTask` 不再产生额外的 `Task` 分配，测试验证了结果值的正确性。

### 1.3 UniTask 版本（Unity Test Framework）

共 **33** 个测试用例，使用 `[UnityTest]` 和 `IEnumerator` 返回执行。测试类结构与 xUnit 版本一致，但由于 Unity 环境限制，接口契约测试使用真实步骤实现，未使用 Mock。

**关键适配点**：
- 所有异步测试通过 `UniTask.ToCoroutine` 或辅助 `Run` 方法转换为协程。
- 取消测试采用 `Task.Delay` 配合 `CancellationToken`，在 `CancelAfter` 后验证 `OperationCanceledException` 被正确抛出。
- 行为链测试中，行为直接返回 `UniTask`（未 `await`），验证同步转发场景下的执行顺序正确性。

**所有单元测试全部通过，验证了三版本的 API 一致性、功能正确性和异常安全性。**

## 总结

1. **单元测试**：三版本共 99 个测试用例全部通过，覆盖了 API 正确性、接口契约、中断策略、行为管道、取消令牌等核心功能，无失败或异常。
2. **基准测试**：Task 版本在 CPU 时间上略有优势，但 ValueTask 版本的内存分配全面领先（节省 12%–37%），GC 回收次数显著减少。
3. **Unity 性能测试**：UniTask 版本在编辑器中的耗时稳定在 4–5 ms/次（极简场景），证明了其底层调度逻辑的高效性，实际构建后性能将进一步提升。
4. **整体评价**：三个版本在功能上完全等价，生产环境选择取决于目标平台和性能关注点。测试数据充分，质量可靠，可放心用于生产项目。
